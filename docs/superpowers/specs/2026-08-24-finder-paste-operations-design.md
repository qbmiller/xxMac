# Finder 粘贴操作设计

## 目标

将现有“粘贴 Finder 文件路径”快捷键迁移到“剪贴板 > 粘贴操作”，并扩展同一快捷键，使用户可以在 Finder 当前文件夹中将剪贴板图片或纯文本直接保存为文件。

默认快捷键继续使用 `Command + Shift + V`。一个快捷键根据剪贴板内容和当前前台应用分流，不注册相互冲突的多个快捷键。

## 设置界面

在“剪贴板”第二栏新增“粘贴操作”，右侧包含三个并列功能区：

1. **粘贴 Finder 文件路径**
   - 展示并编辑共用快捷键。
   - 从“通用 > 快捷键管理”迁移到此处。
   - 保留现有默认快捷键和快捷键冲突检查。
2. **图片转文件**
   - 独立开关，默认关闭。
   - 显示当天的下一个编号。
   - 提供“重置”按钮，将当天的下一个编号设为 `001`。
3. **文本转文件**
   - 独立开关，默认关闭。
   - 显示当天的下一个编号。
   - 提供“重置”按钮，将当天的下一个编号设为 `001`。

图片和文本使用彼此独立的每日计数。日期变化后自动从 `001` 开始；重启 xxMac 后，当天计数仍然保留。

开关、计数日期和下一个编号写入配置目录中的 `preferences.json`。不创建新的缓存目录，用户生成的文件只写入 Finder 当前目录。

## 快捷键分流

触发共用快捷键后按以下优先级处理：

1. **剪贴板包含文件 URL**
   - 始终优先判定为 Finder 文件复制。
   - 沿用现有“粘贴 Finder 文件路径”行为，将完整路径输入当前前台应用。
   - 不受图片转文件或文本转文件开关影响。
   - 即使复制的文件本身是图片或文本，也绝不转换成新文件。
2. **Finder 前台且剪贴板包含原始位图**
   - 图片转文件开关开启时，保存为 PNG。
   - 开关关闭时不执行。
3. **Finder 前台且剪贴板包含纯文本**
   - 文本转文件开关开启时，保存为 UTF-8 文件。
   - 开关关闭时不执行。
4. **其他情况**
   - 不执行任何操作。

图片和文本转文件严格限制为 Finder 前台。现有文件路径粘贴不增加 Finder 前台限制，因此仍可将 Finder 中复制的路径粘贴到终端、编辑器或聊天应用。

## Finder 目标目录

目标目录通过 Finder Apple Events 获取：

- 有活动 Finder 窗口时，使用该窗口当前显示的文件夹。
- Finder 前台但没有活动窗口时，使用桌面目录。
- 无法可靠取得目录时，不创建文件、不增加计数，并向用户显示失败通知。

首次使用时，macOS 会请求 xxMac 控制 Finder 的“自动化”权限。用户拒绝或后续关闭该权限时，目录查询失败并进入上述失败流程。

目标必须是可写目录。目录不可写或写入失败时，按失败流程处理。

## 文件命名与计数

基础文件名格式为 `yyyyMMdd-NNN`：

- 图片示例：`20260825-001.png`
- 已识别文本示例：`20260825-001.json`
- 未识别文本示例：`20260825-001`

`NNN` 至少补齐三位；超过 `999` 后自然使用 `1000`、`1001`，不截断。

不扫描目标目录来推导编号。图片和文本分别读取持久化的“计数日期 + 下一个编号”。只有文件成功写入后，对应的下一个编号才加一。

若基础文件名已经存在，不覆盖原文件，改用 `yyyyMMdd-NNN-<Unix 秒时间戳>.ext`。如果该名称仍冲突，则使用 Unix 毫秒时间戳；若毫秒名称仍冲突，则在其后追加从 `-1` 开始的最小可用序号。该冲突检查只针对本次候选文件名，不用于扫描或恢复计数。

## 图片处理

只处理剪贴板中的原始位图数据，例如 macOS 截图或网页复制的图片。文件 URL 判定优先，因此 Finder 中复制的图片文件不会进入此流程。

图片使用 AppKit 解码并统一编码为 PNG。解码、编码和文件写入在后台队列执行，避免阻塞 Finder 或应用主线程。

## 文本格式识别

文本完整保留，以 UTF-8 写入。格式识别应保守，不能可靠识别时不添加扩展名。

首版支持：

- JSON：严格 JSON 解析成功，扩展名 `.json`。
- Property List：Property List 解析成功；XML plist 使用 `.plist`。
- XML：严格 XML 解析成功，扩展名 `.xml`。
- YAML：符合明确的 YAML 映射、列表或文档标记特征，扩展名 `.yml`。
- TOML：符合明确的 TOML 表、键值和语法特征，扩展名 `.toml`。
- INI：符合节名和键值结构，扩展名 `.ini`。
- ENV：非空有效行主要由环境变量形式的 `KEY=VALUE` 构成，扩展名 `.env`。

识别顺序为 JSON、plist、XML、YAML、TOML、INI、ENV。识别器必须避免将普通单行文本、自然语言或只有一个模糊键值对的内容强行归类。

## 组件边界

实现拆分为以下职责：

- `FinderPasteOperationManager`：接收共用快捷键并按剪贴板内容、前台应用和设置进行分流。
- 剪贴板载荷判定：优先识别文件 URL，其次原始位图，最后纯文本。
- Finder 目录解析：只负责返回活动目录或明确失败。
- 文件命名器：根据日期、计数、扩展名和冲突状态生成候选名称。
- 文本格式识别器：纯函数，将文本映射为可选扩展名。
- 设置状态：持久化开关、计数日期和下一个编号，并在日期变化或用户重置时更新。

现有 `FilePathPasteManager` 的路径读取、Shell 转义和文字输入能力继续复用。现有 `WindowAction.pasteFinderPath` 及其快捷键注册可以保留兼容名称，但触发入口改为新的分流管理器。

## 错误与反馈

- 图片解码失败、Finder 目录不可用、目录不可写或写入失败时，不增加计数。
- 保存成功后显示文件名和目标目录通知。
- 保存失败时显示简短错误通知，不修改剪贴板内容。
- 文件路径粘贴保持现有行为，未检测到文件 URL 时不伪造路径内容。

## 文档与配置目录

README 增加 Finder 粘贴操作、默认快捷键、图片和文本开关、命名与格式识别说明。

“通用 > 配置目录”相关说明同步注明：图片/文本粘贴开关及每日计数保存在 `preferences.json`；实际生成的文件不在配置目录中，也不随“导出配置”导出。

## 测试与验证

单元测试覆盖：

- 文件 URL 的分流优先级，以及复制图片文件/文本文件时不进入转换流程。
- 图片、文本开关默认关闭及各自开关判定。
- 图片和文本转换只在 Finder 前台执行。
- 文件路径粘贴在非 Finder 前台应用中继续工作。
- JSON、plist、XML、YAML、TOML、INI、ENV 的正例与容易误判的反例。
- 图片和文本每日独立计数、日期变化重置、手动重置。
- 编号至少三位并能超过 `999`。
- 基础名称冲突后使用秒、毫秒和最终序号兜底，且不覆盖文件。
- 写入成功后递增，转换或写入失败时不递增。
- 设置持久化和旧版本配置缺少新字段时采用默认值。
- 快捷键设置迁移后仍参与现有冲突检测。

验证命令：

```bash
swift test
swift build
```

应用包内手动验证：

1. 在 Finder 当前目录用 `Command + Shift + V` 将截图保存为 PNG。
2. 将大 JSON、YAML 和普通文本分别保存并检查扩展名与内容完整性。
3. 复制 Finder 文件，在终端或编辑器触发快捷键并确认仍粘贴完整路径。
4. 关闭各开关后确认相应转换不执行。
5. 重置编号、跨日期状态模拟和同名文件场景不覆盖已有文件。
