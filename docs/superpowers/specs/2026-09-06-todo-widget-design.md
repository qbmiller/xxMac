# Todo 桌面小组件设计

## 目标

为 xxMac 的 Todo 功能增加原生 macOS 桌面小组件。用户可通过 macOS 的“编辑小组件”自行添加、移动或移除该组件，并可直接在组件内将任务标记为已完成。

本期只增加 WidgetKit 小组件及其数据同步能力，不修改现有 Todo 窗口的层级、置顶、跨 Space、工具栏或其他窗口行为。

## 系统与尺寸范围

- 桌面放置和交互能力要求 macOS 14 或更高版本。
- 使用 WidgetKit、SwiftUI 和 AppIntent。
- 首版只支持 `.systemMedium`。
- 不实现小号、大号、超大号、锁屏组件或通知中心专用布局。
- WidgetKit 负责刷新调度，小组件不承诺实时轮询数据库。

## 工程边界

主应用继续保持现有 Swift Package 工程和构建方式：

- `Package.swift` 继续定义并构建 xxMac 主应用。
- 主应用日常编译和测试继续使用 `swift build`、`swift test`。
- 不把主应用迁移为 Xcode 工程。

在仓库根目录新增独立的 `TodoWidget/` 文件夹，包含：

- Todo Widget Extension 的 Xcode 工程。
- WidgetKit 入口、Timeline Provider、SwiftUI 视图和 AppIntent。
- Widget Extension 的 `Info.plist`、Entitlements 和资源。
- 仅供主应用与扩展共享的轻量数据模型源码。

`bundle_app.sh` 在主应用构建完成后，只对 `TodoWidget/` 中的扩展工程运行 `xcodebuild`，将生成的 `.appex` 嵌入 `xxMac.app/Contents/PlugIns/`。扩展先单独签名，最后再签名主应用。日常 `swift build` 不隐式构建或安装小组件。

扩展标识使用 `com.xiaomi318.xxMac.TodoWidget`，App Group 使用 `group.com.xiaomi318.xxMac`。主应用和扩展分别声明所需 entitlement。

## 小组件内容

小组件显示所有未完成、未归档任务，最多展示 10 条，采用单列紧凑布局。

顶部显示 Todo 标题以及当前展示数和未完成总数，例如 `Todo 10/23`。任务不足 10 条时只显示实际任务数；没有任务时显示空状态。

每一行包含：

- 左侧可点击完成圆圈。
- 紧凑的类别标识，用于区分今日、进行中和待办。
- 单行任务标题，空间不足时尾部截断。
- 今日任务可显示简短截止时间或逾期标识，但不能挤占完成按钮的点击区域。

不使用独立分组标题，以便中号尺寸容纳 10 行。点击任务标题或组件非按钮区域时打开 xxMac Todo；点击完成圆圈只执行完成操作，不打开主应用。

## 筛选与排序

候选任务必须同时满足：

- `archivedAt == nil`
- `status != completed`

任务按以下优先级组成一个无重复列表：

1. 今日：截止时间早于明天本地零点，包括已逾期和今天到期的未完成任务。
2. 进行中：状态为 `inProgress`，但未进入今日组的任务。
3. 待办：状态为 `todo`，但未进入今日组的任务。

今日组按截止时间升序排列，截止时间相同时按更新时间降序。进行中和待办分别按 `statusRank` 升序排列，排序值相同时按更新时间降序。最终取前 10 条。

“今日”使用当前 Mac 的日历、时区和本地零点边界。跨越午夜后 Timeline 必须安排刷新，使任务能够进入或离开今日优先区。

## App Group 数据

现有 `todo.db` 继续保存在用户选择的配置目录中，并保持主应用的权威数据源。小组件不直接打开用户配置目录中的 SQLite 文件。

App Group 共享容器保存两类数据：

- `todo-widget-snapshot.json`：小组件渲染所需的精简任务快照。
- `todo-widget-actions.json`：小组件产生、尚待主应用确认写入 SQLite 的持久操作日志。

快照只包含小组件所需字段，例如任务 ID、标题、状态、截止时间、更新时间和排序值，不复制备注等无关内容。文件写入使用临时文件加原子替换，避免扩展读取到半写入内容。

App Group 文件不属于用户可配置的数据目录，不随“通用 > 配置目录”迁移。README 和配置目录说明必须明确：`todo.db` 仍随配置目录迁移，小组件快照及操作日志由系统 App Group 管理，可由主应用重新生成。

## 主应用发布快照

主应用在以下时机处理待完成操作并重新发布快照：

- TodoStore 初始化并完成数据库加载后。
- 新建、编辑、状态切换、撤回、归档、恢复、删除或排序成功后。
- 配置目录迁移并重新打开 Todo 数据库后。
- 应用启动、重新激活或收到小组件操作通知时。

必须先把待处理操作幂等写入 `todo.db`，再根据最新数据库状态生成快照。快照发布完成后调用 `WidgetCenter.reloadTimelines(ofKind:)`。

如果主应用当前未运行，操作日志继续保留；下次启动时必须先消费日志再发布快照，防止已在小组件中完成的任务重新出现。

## 完成交互

完成按钮调用 `CompleteTodoIntent`，参数为稳定的任务 UUID。

Intent 执行流程：

1. 在 App Group 操作日志中追加带唯一操作 ID 的完成命令。
2. 从共享快照中移除该任务，使组件立即反映完成结果。
3. 原子写回日志与快照。
4. 发送进程间变更通知，并请求刷新 Todo Widget Timeline。

主应用运行时监听该通知并立即消费操作；未运行时不强制打开主应用。每条操作使用唯一操作 ID，并以任务 ID 做状态检查：任务已完成、已归档或已删除时，重复操作视为已处理，不再次改变状态。

主应用成功应用完成操作时，复用现有 TodoStore 状态流转规则，包括设置 `completedAt`、记录完成前状态、更新 `updatedAt` 和取消对应截止通知。

如果 AppIntent 写入共享容器失败，小组件不得显示假成功状态，应保留当前任务并让系统后续重新加载快照。

## 一致性与冲突

- 主应用发布快照前先消费操作日志，避免用旧数据库状态覆盖小组件的乐观更新。
- 小组件只允许完成任务，不支持撤回、编辑、删除、排序或新建。
- 主应用对同一任务的后续编辑以数据库最终状态为准，并重新生成快照。
- 日志消费成功后删除对应操作；消费中断时保留未确认操作供下次重试。
- 无法解析的快照不导致扩展崩溃，小组件显示空状态或上次有效内容。

## 本地化与视觉

新增文案覆盖简体中文、繁体中文和英文。组件使用系统背景、语义颜色和 SF Symbols，适配浅色、深色以及 macOS 桌面小组件的着色模式。

10 行单列是明确的产品选择。布局优先保证完成圆圈可辨识、任务标题可扫描以及整行不重叠；标题统一单行截断，不通过横向滚动或自动缩小到不可读字号来展示全文。

## 打包与签名

`bundle_app.sh` 增加以下步骤：

1. 使用现有流程构建主应用。
2. 构建 Todo Widget Extension。
3. 创建 `xxMac.app/Contents/PlugIns/` 并复制 `.appex`。
4. 使用同一签名体系签名扩展，保留扩展沙盒和 App Group entitlement。
5. 使用包含 App Group entitlement 的主应用配置签名 xxMac。
6. 验证主应用、嵌入扩展、Bundle ID、App Group entitlement 和嵌套签名。

若当前签名证书或 Provisioning Profile 不支持 App Group，打包必须明确失败，不得静默移除 entitlement 或退回成没有数据共享能力的小组件。

## 验证

自动验证至少覆盖：

- 未完成、未归档筛选。
- 今日、进行中、待办的优先级和去重。
- 今日组、状态组内部排序。
- 最多取 10 条。
- 跨午夜 Timeline 刷新时间计算。
- 快照原子读写和损坏数据回退。
- 完成日志的幂等消费与失败重试。
- 主应用消费完成操作后使用现有完成状态规则。
- 配置目录迁移后重新发布小组件快照。

构建验证包括 `swift test`、Todo Widget Extension 构建、`bundle_app.sh` 生成应用、`codesign` 嵌套签名和 entitlement 检查。

真实验收需要在 macOS 14 或更高版本上安装生成的 `xxMac.app`，确认系统“编辑小组件”能找到 xxMac Todo，手动添加中号组件，并验证主应用运行和未运行两种情况下完成任务都不会恢复。安装和桌面添加属于运行时验收，不能只用编译通过替代。

## 非目标

本期不包含：

- Todo 主窗口置顶或图钉功能。
- Todo 主窗口层级、Space 或显示行为调整。
- 小组件内新建、编辑、撤回、删除或拖动排序。
- 小号、大号、超大号或多种组件配置。
- iCloud、CloudKit 或跨设备同步。
- 实时数据库监听或高频 Timeline 刷新。
