# 待办与四象限设计

## 目标

为 xxMac 增加独立的本地待办工具。用户通过默认全局快捷键
`Command + Option + T` 打开一个可关闭、可调整大小的浮动窗口，在同一窗口中
使用四象限、列表、今日筛选和状态看板管理任务。

首版只使用本地 SQLite，不实现 iCloud 或其他网络同步。数据模型使用稳定 UUID、
更新时间和独立删除语义，为后续接入 CloudKit 保留演进空间，但不提前实现同步队列、
冲突合并或账号配置。

## 核心概念

任务的执行状态、四象限、截止时间和生命周期是四个独立维度：

- 执行状态：待办、进行中、已完成。
- 四象限：重要且紧急、重要不紧急、不重要但紧急、不重要不紧急。
- 截止时间：可为空；设置时精确到分钟。
- 生命周期：正常、已归档。删除是永久操作，不作为普通任务状态。

“今日”和“已逾期”是根据截止时间计算的筛选结果，不写入任务状态。完成任务继续
保留原四象限，四象限页面默认以划线样式显示，也允许临时隐藏。

## 任务模型

`TodoTask` 至少包含：

- `id`：UUID 字符串，创建后不变。
- `title`：必填，去除首尾空白后不能为空。
- `notes`：可为空的纯文本备注。
- `status`：`todo`、`inProgress`、`completed`。
- `quadrant`：四象限枚举，默认 `notImportantNotUrgent`。
- `dueAt`：可空时间戳，精确到分钟。
- `createdAt`、`updatedAt`：创建及最后修改时间。
- `completedAt`：进入已完成状态时记录；离开已完成状态时清空。
- `statusBeforeCompletion`：记录进入已完成前的执行状态，用于撤回后准确恢复。
- `archivedAt`：归档时记录；恢复时清空。
- `quadrantRank`：四象限栏内手动排序值。
- `statusRank`：状态看板栏内手动排序值。

首版不包含标签、附件、子任务、重复任务、负责人、完成百分比和多级优先级。

## 状态流转与撤回

用户可通过任务操作菜单、详情编辑或看板拖拽直接切换到任意执行状态。撤回不是通用
编辑历史，也不保存连续撤销栈：

- 已完成任务显示“撤回”，执行后恢复到完成前的待办或进行中状态。
- 进行中任务显示“撤回”，执行后变为待办。
- 待办任务不显示“撤回”。

任务进入已完成状态时会持久化记录完成前状态。旧数据库中的已完成任务没有该记录时，
撤回仍按兼容逻辑进入进行中。标题、备注、象限、截止时间、排序、归档和删除不受状态撤回影响。

任务进入已完成状态时设置 `completedAt`。任务离开已完成状态时清空
`completedAt`。状态变化总是更新 `updatedAt`，并把任务插入目标状态栏的末尾。

## 窗口行为

待办使用独立 `NSPanel`/`NSWindowController`，不复用启动器面板，也不嵌入设置窗口。
窗口具备以下行为：

- 默认浮动在普通应用窗口之上。
- 可关闭、移动和调整大小。
- 可加入所有 Space，并支持全屏辅助显示。
- 再次触发热键时，隐藏可见窗口；窗口隐藏时触发则恢复并聚焦。
- 首次打开使用紧凑尺寸，后续恢复用户上次的位置和尺寸。
- 设置最小尺寸，保证顶部导航、搜索和任务编辑控件不会重叠。

窗口右上角提供“展开看板/恢复窗口”按钮：

- 紧凑模式显示常规多视图界面。
- 展开模式切换为宽屏三栏状态看板。
- 两种模式分别记忆窗口 frame。
- 展开和恢复时将目标 frame 限制在当前屏幕可见区域内。

窗口使用标准标题栏关闭、最小化和缩放控件，不制作无边框伪窗口。

## 紧凑模式视图

顶部导航包含以下视图：

1. 四象限：默认视图，使用 2×2 网格。
2. 全部：可在卡片和列表两种布局之间切换。
3. 今日：显示已逾期未完成、今日未完成和今日已完成任务。
4. 待办：只显示正常生命周期中的待办任务。
5. 进行中：只显示正常生命周期中的进行中任务。
6. 已完成：只显示正常生命周期中的已完成任务。

归档任务不进入以上任何普通视图。归档入口放在工具栏的更多菜单中，打开独立归档
列表；归档列表支持搜索、查看、恢复和永久删除。

### 四象限

四象限固定为：

- 左上：重要且紧急。
- 右上：重要不紧急。
- 左下：不重要但紧急。
- 右下：不重要不紧急。

每个象限显示任务数量，并支持象限内拖动排序和跨象限拖动。跨象限只改变
`quadrant` 和象限排序值，不改变执行状态。完成任务默认仍在对应象限显示，标题划线、
整体弱化，并保留撤回操作。工具栏提供“隐藏已完成”开关，该开关只影响四象限页面的
临时显示，不修改任务数据。

### 全部

全部视图包含卡片/列表分段控件。两种布局使用同一查询结果和选择状态，切换布局不会
改变排序或筛选。默认按最近更新时间降序；用户可以选择按创建时间、截止时间或执行
状态排序。本期不在全部视图中维护额外手动排序。

### 今日

今日视图按以下顺序分组：

1. 已逾期且未完成。
2. 今天截止且未完成。
3. 今天截止且已完成。

组内按截止时间升序，再按更新时间降序。已完成任务划线显示。没有截止时间的任务不进入
今日视图；过去日期已经完成的任务也不进入今日视图。

“今天”以当前 Mac 的日历、时区和本地零点边界计算。应用跨越午夜运行时必须刷新筛选，
不能要求重启应用。

### 状态列表

待办、进行中和已完成视图分别使用对应 `statusRank` 排序，并支持栏内手动拖动排序。
进行中和已完成任务显示撤回按钮，待办任务不显示。

## 展开状态看板

展开模式使用横向三栏：待办、进行中、已完成。每栏显示任务数量，任务按
`statusRank` 排序。

- 栏内拖动更新 `statusRank`。
- 跨栏拖动更新执行状态，并把任务插入目标位置。
- 已完成栏任务使用划线样式。
- 进行中和已完成卡片显示撤回按钮。
- 搜索条件继续生效，只允许拖动当前可见任务；排序计算仍基于该栏全部正常任务，避免
  清除搜索后顺序损坏。

状态看板不是四象限的替代视图。四象限继续保留在紧凑模式的独立标签中。

## 新建与编辑

主窗口提供明显的新增按钮，并支持 `Command + N`。触发新增后自动聚焦标题输入框。

新任务默认值：

- 状态为待办。
- 象限为不重要不紧急。
- 截止时间为空。
- 插入默认象限和待办状态栏的末尾。

任务详情允许编辑标题、备注、状态、四象限和截止时间。标题为空时不能保存，并在输入框
附近显示校验信息，不使用模态错误弹窗。

- 宽度足够时，详情显示在窗口右侧检查器中。
- 窗口较窄时，详情使用 sheet。
- 双击任务或选中后按 Return 打开详情。
- Escape 关闭未提交的详情编辑；保存成功后立即刷新所有关联视图。

## 搜索、排序和拖拽

搜索不区分大小写，匹配标题和备注。搜索条件作用于当前视图，不包含归档任务；归档页面
使用自己的搜索状态。

手动排序采用可留间隔的浮点或整数 rank。插入两个任务之间时优先计算中间值；间隔不足
时只重排目标象限或目标状态栏，不重排所有任务。

任务同时拥有 `quadrantRank` 和 `statusRank`，原因是象限位置与状态看板位置互相独立。
在四象限拖动不会意外改变状态栏顺序，在状态看板拖动也不会改变象限顺序。

## 归档与删除

- 归档设置 `archivedAt`，任务从普通视图隐藏，但数据继续保留。
- 恢复归档清空 `archivedAt`，任务回到原执行状态、象限及排序位置。
- 删除必须显示二次确认，确认后从数据库永久删除。
- 已完成不自动归档，也不提供首版自动归档策略。

## 截止通知

设置未来截止时间时，为任务安排一条 macOS 本地通知。首次真正需要安排通知时再请求通知
权限，不在应用启动时主动弹出权限请求。

- 通知标题使用任务标题，正文显示“任务已到截止时间”。
- 编辑截止时间或标题后重建对应通知。
- 清除截止时间、完成、归档或删除任务时取消待发送通知。
- 从已完成撤回、从归档恢复时，若截止时间仍在未来则重新安排通知。
- 截止时间已经过去时不补发通知，界面只显示逾期状态。
- 用户拒绝通知权限不影响任务保存；设置页显示通知不可用状态和系统设置入口。

通知标识使用任务 UUID，确保修改与取消具有确定性。本期不增加独立提醒时间、提前提醒、
重复提醒或稍后提醒。

## SQLite 持久化

在当前配置目录新增独立 `todo.db`。数据库使用 WAL，并通过 `PRAGMA user_version` 管理
schema 版本。首版表结构至少包含任务表及支持状态、象限、截止时间、归档和搜索的索引。

数据库访问封装在独立存储类型中，不把 SQL 放进 SwiftUI View。存储层提供：

- 初始化及 schema 迁移。
- 新增、读取、更新和永久删除。
- 普通任务与归档任务查询。
- 标题和备注搜索。
- 批量更新排序值。

所有写操作串行执行，完成后在主线程发布新快照。SQLite 错误写入诊断日志，并在待办窗口
显示可恢复的内联错误；失败的写操作不得先修改内存状态造成假成功。

## 配置目录与未来同步

配置目录迁移必须包含：

- `todo.db`
- `todo.db-wal`
- `todo.db-shm`

迁移前关闭或 checkpoint 待办数据库，迁移后从新目录重新打开。迁移失败时恢复旧目录连接，
不能留下窗口可编辑但数据库已关闭的状态。

“导出配置”继续只导出可配置设置，不导出 `todo.db`。README 和“通用 > 配置目录”必须
明确：切换配置目录会迁移待办数据库，但导出配置不会备份任务数据。

首版不把 SQLite 文件直接放入 iCloud Drive，也不实现 CloudKit。为未来同步保留的边界是：
稳定 UUID、明确 `updatedAt`、独立持久化接口和可迁移 schema；不增加未使用的云字段。

## 热键、菜单和设置

新增待办入口动作，默认快捷键为 `Command + Option + T`。快捷键可以修改或清除，并进入
现有统一快捷键冲突检测，不能与窗口管理、启动器、剪贴板、Snippets 或应用快捷启动重复。

菜单栏菜单增加“待办”，触发与全局热键相同的窗口切换行为，并显示当前快捷键。

设置左侧增加“待办”工具，详情页包含：

- 待办窗口快捷键录制与清除。
- 通知授权状态和系统设置入口。
- 打开待办数据库所在目录的入口。

窗口尺寸、上次普通视图、全部视图布局和四象限“隐藏已完成”偏好写入
`preferences.json`。任务内容只写入 `todo.db`。

## 本地化与视觉设计

新增文案同时覆盖简体中文、繁体中文和英文。界面使用系统语义颜色和 SF Symbols，适配
浅色、深色及减少动态效果设置。

视觉结构参考用户提供的微软 Todo/滴答清单风格截图，但截图中的示例任务、日期、数量、
按钮文本和外部视频叠层不属于产品需求。界面重点是可扫描的顶部导航、清晰的任务卡片、
克制的状态颜色和紧凑的桌面信息密度。

四象限使用四种可区分但低饱和的强调色；逾期使用系统红色，今日使用系统橙色，完成使用
次级文本和划线，不使用大面积单色背景。

## 组件边界

实现拆分为以下职责：

- `TodoModels`：任务、状态、象限、筛选和排序模型。
- `TodoStore`：可观察任务状态、用户操作协调和错误发布。
- `TodoDatabase`：SQLite schema、查询与事务。
- `TodoNotificationManager`：通知权限、安排和取消。
- `TodoWindowController`：独立窗口创建、显示、展开和 frame 恢复。
- `TodoRootView`：顶部导航、搜索和当前视图切换。
- 四象限、列表、今日、状态看板和任务编辑器使用独立 View 文件。

View 不直接访问 SQLite、`UNUserNotificationCenter` 或全局热键对象。窗口控制器不包含任务
筛选和排序规则。

## 错误处理

- 数据库初始化失败时窗口显示不可编辑的错误状态和重试按钮。
- 单次写入失败时保留原任务快照，并显示内联错误。
- 无法注册默认热键时不阻止应用启动，在设置页显示冲突或注册失败状态。
- 通知权限拒绝只影响通知，不影响截止时间。
- 拖拽目标失效或任务已被删除时取消本次操作，不崩溃、不创建重复任务。

## 自动化测试

至少覆盖：

- 新任务默认状态、默认象限和空截止时间。
- 三种状态的撤回目标，以及待办不可撤回。
- 进入和离开已完成时 `completedAt` 的变化。
- 今日、已逾期和跨午夜筛选边界。
- 标题和备注搜索。
- 四象限与状态排序值互不干扰。
- 栏内排序和跨栏插入。
- 归档、恢复和永久删除。
- SQLite 建表、CRUD、索引查询和 schema 版本。
- 配置目录迁移包含数据库、WAL 和 SHM。
- 通知安排、更新、取消条件的纯策略。
- 默认 `Command + Option + T` 及统一冲突检测。
- 普通/展开窗口 frame 策略和屏幕边界限制。

完整验证运行 `swift test` 和 `swift build`。

## 手工验收

使用 `bundle_app.sh` 生成并启动应用后验证：

1. 默认快捷键打开、隐藏并再次恢复待办窗口。
2. 调整窗口大小和位置后重开仍能恢复。
3. 展开为三栏状态看板，再恢复紧凑窗口，两种 frame 分别保持。
4. 新建、编辑、搜索、归档、恢复和永久删除任务。
5. 四象限跨区拖动只改变象限，状态看板跨栏拖动只改变状态。
6. 已完成任务在四象限划线显示，隐藏开关只影响可见性。
7. 进行中和已完成任务撤回一级，待办没有撤回按钮。
8. 今日页面正确显示逾期、今日未完成和今日已完成分组。
9. 允许通知后，未来截止时间产生系统通知；修改、完成或删除后旧通知被取消。
10. 浅色、深色和小窗口下没有文字截断、控件重叠或不可达操作。

构建和自动化测试通过不等于上述窗口、拖拽和通知体验已经验收；最终结果必须分别报告。

## 非目标

- iCloud、CloudKit、微软 Todo、滴答清单或其他服务同步。
- 多用户、共享清单和协作。
- 标签、附件、子任务和重复任务。
- 自定义工作流状态。
- 通用编辑撤销栈或状态历史审计。
- 回收站、自动归档和自动删除。
- 独立提醒时间、提前提醒和重复通知。
