# 自动覆盖更新实施计划

目标：使用 Sparkle 2 下载、校验、覆盖并重新启动 xxMac；保留现有更新检查周期，新增自动安装开关。

架构：现有 UpdateManager 调度检查。Sparkle 独立负责受签名保护的更新安装；下载完成后通过立即安装回调请求重启。未配置更新公钥时禁用安装并提示原因，不影响旧版检查。

- [x] 引入 Sparkle，并检查实际 SDK 接口。
- [x] 增加可测试的更新安装策略、自动安装开关及设置/启动器入口。
- [x] 修改打包脚本嵌入并签名框架，增加本地更新包及 appcast 生成命令；不发布远端。
- [x] 更新三种语言、配置目录说明及 README。
- [x] 定向测试、完整 SwiftPM 测试、脚本语法及应用包验证。

约束：不操作 GitHub、不覆盖用户配置；签名私钥不入库；系统可能要求管理员授权。
验证重点：关闭开关不重启、重复检查不重复安装、缺公钥不安装、下载/校验失败保留旧应用、重启前沿用应用正常退出流程。

## 验证记录

- Sparkle 2.10.1 官方 SwiftPM 二进制依赖及校验和已解析。
- `swift test`：297 项通过；应用包和所有嵌套 Sparkle 组件签名验证通过。
- `make prepare-update`：本地生成 1.2.5 ZIP 和 appcast，未上传。
- 独立 CryptoKit 验证：ZIP 签名匹配应用公钥，篡改文件被拒绝。
- 脚本语法、plist/三语言 strings、diff 空白检查通过。
- 无远端 feed 发布；尚未进行两个不同版本之间的实际覆盖与重启测试。
- 实施选择：安装开关默认关闭，更新检查默认每周，现有用户需手动安装一次。

## 审查修复

- 手动检查不再被后台会话去重拦截；已有更新可由标准控制器重新展示。
- 保留立即安装 handler，以便关闭开关后手动恢复，以及应用取消退出后重试；新增 2 项测试。
- 框架及发布工具从实际 artifact 目录查找，不绑定仓库 checkout 名称。
- 文档澄清：关闭开关可停止立即重启，已经排队的 Sparkle 更新仍可能在退出时安装。

## 发布流程整合（用户追加要求）

`make deploy` 在 DMG 验证后自动调用 prepare_update.sh，传递实际应用路径、输出目录及 RELEASE_TAG；确认后同一次 gh release create 带上 DMG、ZIP 和 appcast.xml。签名生成失败、材料缺失或 SKIP_BUILD 的应用版本不匹配时停止发布。保留独立 make prepare-update；不发布时仍生成本地三份材料。
验证：Tests/Shell/publish_dmg_test.py 的 6 项隔离模拟测试通过（不访问网络），脚本语法及 diff 检查通过。未运行真实 GitHub 发布。
